# internal/config

В этом пакете хранятся конфигурации приложения.

Загрузку конфигурации можно реализовать из различных источников, например: файлов, переменных окружения, баз данных и других.

## Параметры аудита

- `--audit-file`, `AUDIT_FILE` — путь к файлу, куда события аудита добавляются в формате JSON Lines. Если значение не задано, файловый приёмник отключён.
- `--audit-url`, `AUDIT_URL` — полный `http` или `https` URL удалённого приёмника. Если значение не задано, удалённый приёмник отключён.

Переменные окружения имеют приоритет над CLI-флагами. Пустые значения из окружения не отключают уже заданные флаги.

## gRPC-сервер

Адрес gRPC-сервера задаётся полем `grpc_address` в JSON-файле, флагом `-g`
или переменной окружения `GRPC_ADDRESS`. Значение по умолчанию —
`localhost:3200`. Приоритет источников совпадает с HTTP:
окружение > CLI > JSON > значение по умолчанию.

Параметры `base_url` и `enable_https` общие для обоих транспортов.
`server_idle_timeout` используется как максимальное время простоя gRPC-соединения,
`server_read_timeout` — как таймаут установления соединения и HTTP/2 handshake,
а `server_write_timeout` — как максимальная длительность unary RPC.

## Доверенная подсеть

Доверенная подсеть для внутренних эндпоинтов задаётся полем `trusted_subnet`
в JSON-файле, флагом `-t` или переменной окружения `TRUSTED_SUBNET`.
Значение должно быть записано в формате CIDR, например `192.168.0.0/24`.

Для этой настройки пустое значение имеет особый смысл: доступ к внутренним
эндпоинтам запрещается для всех запросов. Поэтому явно заданная пустая
`TRUSTED_SUBNET` переопределяет значения из JSON-файла и CLI.
Некорректное непустое значение не позволяет запустить HTTP-сервер.
